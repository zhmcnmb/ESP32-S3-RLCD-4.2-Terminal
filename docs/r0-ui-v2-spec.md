# R0 架构优化与 UI V2 规格

> 状态：方案设计，尚未实现
> 日期：2026-07-15
> 范围：P0-P4 架构治理、现有四个页面视觉升级、P5 接入前置条件
> 硬件基线：400×300 ST7305 单色反射屏、KEY/BOOT 两个可编程按键

## Problem Statement

当前固件已经完成时钟、环境趋势、天气和 Claude 用量四个页面，并经过真机验证，但现有实现和长期智能体规划之间存在结构缺口：页面直接读取设备与业务数据，`ui_manager` 同时负责页面调度和 GPIO 手势，`app_main` 承担全部启动编排，网络事件回调包含阻塞等待，天气与额度客户端重复实现网络骨架，`storage_sd` 的 Interface 也不足以承载录音、会话、Skill 和长期记忆。

这些问题在 P0-P4 阶段尚可控制；继续叠加语音、流式模型、工具调用、SD 长期记忆和任务调度后，会让并发、失败恢复和依赖关系扩散到页面及调用方。

当前界面已经做到内容完整，但四页都采用“外框 + 标题 + 圆角卡片 + 底部提示”的相似构图，信息层级、页面辨识度和单色屏特性利用不足：

- 每页重复 396×296 外框，占用视觉空间但不传递状态。
- 标题、数据新鲜度、主体内容和按键提示之间层级差异偏弱。
- 首页、天气和用量页的圆角卡片较多，单色屏上容易显得拥挤。
- 环境趋势缺少当前值、时间方向和采样状态的快速识别。
- 空数据、离线、等待和错误状态的视觉语言不统一。
- KEY/BOOT 的提示只覆盖现有翻页，未给长按语音和确认/取消预留统一位置。

用户需要的是在不破坏 P0-P4 已验证行为的前提下，先完成一轮可控的架构治理，并把现有页面升级成清晰、克制、有设备辨识度的单色仪表界面，为后续语音智能体提供稳定的状态、输入和视觉基础。

## Solution

实施一个“R0 架构治理 + UI V2”增量版本：

1. 用 `app_runtime` 收拢启动顺序、页面注册和可选能力降级。
2. 用 `sys_state` 提供线程安全状态快照、事件和命令，使页面与 agent 工具读取同一份权威状态。
3. 用 `input_manager` 统一 KEY/BOOT 消抖、长短按与语义事件。
4. 深化 `storage_sd`，使后续录音、会话、Skill 和记忆共用一个持久化 Interface。
5. 修复 WiFi 事件回调阻塞和延迟联网不启动 SNTP 两个确定性问题。
6. 保持 `ui_page_t` 为页面的最高层 seam，在 `ui_pages` 内部建立共享但不公开的 UI V2 视觉原语。
7. 将四个现有页面重排为“单色仪表 / 编辑排版”风格：高对比标题栏、超大核心数字、少量实线、稳定留白、统一状态和底部导航。
8. 以状态快照和语义输入驱动页面，只有可观察状态变化时才重绘，减少无意义整屏刷新。

完成后，用户仍然通过 KEY 翻页、BOOT 执行页面动作，但能获得更清晰的一眼信息、更一致的异常提示，以及为长按说话、确认和取消预留好的交互语言。P0-P4 的数据来源和业务行为保持不变。

## User Stories

1. As a 桌面终端用户, I want 首页一眼显示当前时间, so that 我不需要辨认多个同等权重的信息块。
2. As a 桌面终端用户, I want 日期、星期和校时状态紧邻时间显示, so that 我能立即判断时间是否可信。
3. As a 桌面终端用户, I want 首页保留温度和湿度摘要, so that 我无需切页也能看到当前环境。
4. As a 桌面终端用户, I want 电池、WiFi 和 SD 状态在所有页面位置一致, so that 我能形成稳定的视觉记忆。
5. As a 桌面终端用户, I want 不同页面具有明显不同的主体构图, so that 我不看标题也能快速识别页面。
6. As a 桌面终端用户, I want 页面减少无意义边框和重复卡片, so that 单色屏上的信息更舒展。
7. As a 桌面终端用户, I want 环境页同时看到当前值和最近一小时趋势, so that 我能同时判断状态与变化方向。
8. As a 桌面终端用户, I want 趋势图明确标出温度、湿度、最大值、最小值和时间方向, so that 曲线不会成为缺乏语义的装饰。
9. As a 桌面终端用户, I want 采样不足时看到统一的“正在积累数据”状态, so that 我知道系统正在工作而不是故障。
10. As a Claude 用户, I want 5 小时和 7 天窗口拥有清晰区分, so that 我不会把两个额度混淆。
11. As a Claude 用户, I want 百分比比进度条更醒目, so that 我可以快速决定是否继续高消耗任务。
12. As a Claude 用户, I want 重置时间以紧凑文本显示, so that 我能判断额度恢复节奏。
13. As a 天气页面用户, I want 温度成为页面最强视觉焦点, so that 远距离也能读取。
14. As a 天气页面用户, I want 天气现象配有简单单色图形, so that 页面更容易扫读并具有设备个性。
15. As a 天气页面用户, I want 湿度、风向风力和数据时间分栏显示, so that 次要信息不会挤成一行。
16. As a 离线用户, I want 等待、离线、数据过期和读取失败使用一致的状态语言, so that 我能判断是暂时不可用还是设备故障。
17. As a 设备用户, I want 所有页面底部始终显示一致的 KEY/BOOT 操作, so that 我不用记忆每页不同的隐藏操作。
18. As a 设备用户, I want KEY 长按说话和 BOOT 长按取消在视觉上有固定位置, so that 语音功能加入后不需要重新学习交互。
19. As a 设备用户, I want 页面切换仍然保持现有顺序, so that UI 美化不会改变已形成的使用习惯。
20. As a 设备用户, I want 页面更新时尽量稳定且不闪烁, so that 反射屏适合作为长期常亮桌面设备。
21. As a 设备用户, I want 网络或 SD 异常不导致页面卡死或重启, so that 核心时钟和本地状态始终可用。
22. As a 设备用户, I want 延迟联网后也能自动校时, so that 开机时网络较慢不会造成长期错误时间。
23. As a 设备用户, I want 按键短按和长按识别稳定, so that 翻页、说话、确认和取消不会误触。
24. As a 固件开发者, I want 页面只消费状态快照, so that 更换传感器、网络来源或 agent 工具时不需要修改页面。
25. As a 固件开发者, I want 启动顺序集中在一个 Module, so that 新增可选功能不会继续扩张入口文件。
26. As a 固件开发者, I want 所有按键手势集中在一个 Module, so that UI 和语音不会分别实现冲突的按键规则。
27. As a 固件开发者, I want SD 写入由一个 Module 串行化, so that 录音、日志、会话和记忆不会并发破坏 FATFS。
28. As a 固件开发者, I want 四个页面复用少量视觉原语, so that 调整标题栏、状态和底部导航只需修改一个位置。
29. As a 固件开发者, I want 页面测试通过 `ui_page_t` 和帧缓冲结果完成, so that 内部绘图函数重构不影响测试。
30. As a 固件开发者, I want UI 测试使用固定状态快照, so that 时间、网络和后台任务不会让截图结果不稳定。
31. As a 后续 agent 开发者, I want `sys_state` 成为 UI 与工具共享的权威读取入口, so that 模型看到的设备状态与屏幕显示一致。
32. As a 后续 agent 开发者, I want UI 为 LISTENING/THINKING/CONFIRM/CANCEL 等状态预留统一覆盖层, so that 语音页接入时不需要重做全部页面布局。

## Implementation Decisions

### 1. 交付边界与实施顺序

- 本规格先完成架构前置和现有四页 UI V2，不同时实现完整语音、agent loop、Web Search 或长期记忆。
- 保持 P0-P4 的页面顺序、数据来源、刷新周期和桥接服务协议，不在视觉改版中改变业务含义。
- 按以下顺序实施，避免同时维护两套数据路径：
  1. 修复网络事件阻塞和延迟联网校时。
  2. 建立最小 `sys_state`，先覆盖首页状态栏、温湿度、电池、天气和额度快照。
  3. 建立 `input_manager`，替换 `ui_manager` 内的 GPIO 轮询与手势判断。
  4. 建立 `app_runtime`，迁移初始化、注册和降级编排。
  5. 深化 `storage_sd` 的并发和原子写能力，但不迁移尚未存在的数据类型。
  6. 引入 UI V2 私有视觉原语，逐页迁移首页、环境、天气、额度。
  7. 每迁移一页即删除该页旧的设备直读路径，禁止新旧状态路径长期并存。

### 2. Module 与 Interface 决策

- `app_runtime` 是启动深 Module。外部只需要启动 Interface；初始化顺序、必选/可选功能、页面注册和降级日志留在 Implementation 内。
- `sys_state` 是状态深 Module。外部只使用 read snapshot、apply event、post command；锁、版本、事件分发和字段一致性留在 Implementation 内。
- `input_manager` 是输入深 Module。外部只接收 NEXT、ACTION、BACK、VOICE、CANCEL 等语义事件；GPIO 电平、稳定时间和长按阈值留在 Implementation 内。
- `ui_manager` 保留页面注册、生命周期、导航和 tick 调度，不再读取 GPIO，也不持有业务状态。
- `ui_page_t` 保持为 UI 的最高外部 seam，不为本次美化新增另一套公开页面框架。
- `ui_pages` 内部增加私有视觉原语，负责页头、状态区、分隔线、核心指标、底部导航、空状态和常用图标。该内部 seam 不暴露给其他 Module。
- `storage_sd` 提供 append、stream read、atomic replace 和 checkpoint 能力；路径约束、单写入任务、互斥、批量同步和掉电恢复留在 Implementation 内。
- `cloud_transport` 在 P5.0 实现，不作为本次 UI V2 的前置；当前天气/额度协议保持不变，只记录其重复网络骨架的后续迁移点。
- 不引入通用主题引擎、布局 DSL、动态 widget 注册或 LVGL。400×300 固定屏幕只需要少量稳定视觉原语。

### 3. `sys_state` 快照范围

本次只纳入已存在页面和全局状态真正需要的数据：

- 时间有效性、当前本地时间和日期。
- 温度、湿度、读取状态和更新时间。
- 电池电压、电量、充电状态和读取状态。
- WiFi 连接状态。
- SD 挂载状态。
- 环境历史采样及总采样数的只读视图。
- 当前天气、可用状态和更新时间。
- Claude 5 小时/7 天额度、可用状态和更新时间。
- 当前页面、输入上下文和后续语音状态的预留枚举。

快照必须是一次一致读取，页面不能为同一帧分别调用多个 getter。R0 不把 agent 会话、记忆索引或未来 Provider 配置提前塞入快照。

### 4. 输入语义

- KEY 短按：NEXT，切换下一页。
- KEY 长按：VOICE，后续进入语音聆听；R0 未接语音时显示短暂“语音功能待接入”反馈，不改变页面。
- BOOT 短按：ACTION；当前四页用于刷新当前视图或执行页面明确动作。
- BOOT 长按：BACK/CANCEL；普通页面无上级时不执行，未来语音/确认状态用于取消。
- PWR：仅为硬件电源开关，不出现在可编程交互规格中。
- 手势只在按键释放或达到长按阈值后发布一次；长按成立后不得再补发短按。
- 输入状态变化不得直接调用页面绘制；只发布语义事件，由 `ui_manager` 按当前上下文分发。

### 5. UI V2 视觉方向

视觉语言定义为“单色仪表 / 编辑排版”：像一台安静的桌面测量设备，而不是移动 App 的卡片集合。

- 画布：400×300，白底黑字，四周安全边距 12px。
- 网格：以 4px 为最小步长，常用间距为 8/12/16/24px。
- 页头：高度约 36px；左侧页面名，右侧全局状态图标或数据状态。
- 主体：约 204px；每页只保留一个最强视觉焦点。
- 页脚：高度约 36px；上方 1px 分隔线，固定显示翻页、说话和页面动作。
- 线条：普通分隔线 1px，强调线/选中态 2px；不再绘制整屏外框。
- 圆角：只用于状态徽标或确有分组意义的区域，半径固定 4px 或 8px；避免每个数据块都套圆角框。
- 黑色实底：用于短标题、状态徽标、进度和确认态，整屏黑色覆盖控制在约 25% 以内。
- 字级：核心数字使用 ASCII scale 6-8；次级数字 scale 2-3；中文标题 scale 1-2；状态与时间戳 scale 1。
- 图标：保持线性单色风格，统一 16px/24px 基准；天气图标可使用 40-48px，但不引入位图资源。
- 文案：优先短词和可扫描数字；等待、离线、过期、失败使用统一术语。
- 不使用动画、灰阶模拟、阴影、渐变、密集纹理或装饰性大边框。

### 6. 共享页面骨架

```text
┌──────────────────────────────────────────────────┐
│ 页面标题                         SD  WiFi  电池   │  0-35
├──────────────────────────────────────────────────┤
│                                                  │
│                 页面核心内容                     │  44-247
│                                                  │
├──────────────────────────────────────────────────┤
│ KEY 翻页          长按说话          BOOT 操作     │  256-299
└──────────────────────────────────────────────────┘
```

实际页面不绘制最外层矩形；图中的边框仅表示画布范围。页头状态图标必须保持固定顺序和基线，数据不可用时改变图标内部形态，不改变占位宽度。

### 7. 首页布局

首页定位为“时钟主屏”，时间占据主要视觉面积，环境信息降为底部摘要。

```text
桌面                                      状态图标
──────────────────────────────────────────────────
                  14:36
              07月15日  星期三
                 时间已校准

温度                         湿度
26.4 C                       58 %
──────────────────────────────────────────────────
KEY 翻页          长按说话          BOOT 刷新
```

- 时间保持超大数字，冒号和秒不抢占主体；秒可使用较小字号放在右上基线。
- 日期和星期放在同一行，校时异常使用反白短徽标“未校时”，不增加长警告句。
- 温度/湿度使用两列开放式指标，中间以短竖线或留白分隔，不使用两个大圆角卡片。
- 页头只保留页面名和电池/WiFi/SD，避免状态栏与主体重复。
- 传感器读取失败时保留两列位置，数值显示 `--`，并在列标题旁显示小型错误标记。

### 8. 环境趋势页布局

环境页定位为“趋势仪表”，先显示当前值，再显示两条共享时间方向的曲线。

```text
环境趋势                              60 条采样
──────────────────────────────────────────────────
26.4 C 当前               58 % 当前

温度  25.8 ───╮_╭──── 26.7
               60 分钟前  →  现在

湿度  55   ──╮__╭───── 61
               60 分钟前  →  现在
──────────────────────────────────────────────────
KEY 翻页          长按说话          BOOT 刷新
```

- 两张厚重圆角卡片改为上下两个趋势带，使用标签、范围和一条基线组织内容。
- 当前值从最新样本读取，放在趋势图上方，避免用户必须估算曲线终点。
- 每条趋势带显示最小/最大范围和“60 分钟前 → 现在”的共享时间语义。
- 采样不足两条时保留趋势带高度，显示“正在积累 1/2”而不是空白大框。
- 曲线超出绘图区时必须裁剪；最大值等于最小值时使用固定最小量程。

### 9. Claude 用量页布局

额度页定位为“预算仪表”，百分比是核心，进度条与重置时间为解释信息。

```text
CLAUDE 用量                          更新 18 秒前
──────────────────────────────────────────────────
 5H     42%    ████████░░░░░░░░
               2 小时 14 分后重置

 7D     71%    ███████████░░░░░
               3 天 8 小时后重置
──────────────────────────────────────────────────
KEY 翻页          长按说话          BOOT 刷新
```

- `5H`/`7D` 使用反白短标签，形成稳定识别锚点。
- 百分比使用 scale 3，进度条改为 8 或 10 段的离散块，符合单色点阵语言。
- 两个窗口使用同一列宽和基线，不再各自套圆角框。
- 用量超过 80% 时不依赖颜色：增加双线进度或 `!` 标记。
- 数据过期但仍有缓存时继续显示数值，同时页头显示“旧数据”；完全无数据时使用统一空状态。

### 10. 天气页布局

天气页定位为“天气海报”，温度和天气图形构成主要识别。

```text
常州武进                              12 分钟前
──────────────────────────────────────────────────
   26 C                         [阴/云图标]
                                阴

湿度 89%          风 东风 0 级          数据 正常
──────────────────────────────────────────────────
KEY 翻页          长按说话          BOOT 刷新
```

- 温度使用 scale 6-7，天气现象和 40-48px 单色图标放在右侧，保持左右重量平衡。
- 首批天气图标只覆盖实际接口高频类别：晴、云/阴、雨、雪、雾；未知类型使用通用圆形天气标记。
- 湿度、风和数据状态在底部三列对齐，不再拼接成长字符串。
- 城市名与配置来源解耦，页面只显示状态快照中的地点显示名。
- 接口不可用但存在旧缓存时显示旧天气并标记“旧数据”；首次无缓存才进入空状态。

### 11. 统一空状态与语音覆盖层

- 等待首次数据：图标 + “正在获取” + 简短补充，不显示错误语气。
- 暂时离线：断开图标 + “网络不可用” + “将自动重试”。
- 服务不可用：服务图标 + “数据暂不可用”，保留页面导航。
- 设备读取失败：对应设备图标 + `--` 数值，不让局部失败占满整个页面。
- 旧缓存：继续展示最后数据，在页头使用反白“旧数据”徽标。
- 未来语音状态使用跨页面底部覆盖层，不新建每页独立样式：
  - LISTENING：黑底反白“正在聆听”。
  - THINKING：黑底反白“正在思考”。
  - CONFIRM：黑底反白“BOOT 确认 / 长按取消”。
  - ERROR：短错误标题 + 可恢复动作，数秒后返回原页面。

### 12. 刷新与性能策略

- 首页时间每秒更新；如果秒显示关闭，可降为每分钟更新。
- 环境趋势只在采样版本变化、进入页面或 BOOT 刷新时重绘。
- 天气和额度只在快照版本变化、进入页面或用于倒计时的可见单位变化时重绘。
- `ui_manager` 可以保持固定 tick，但页面不得在内容未变化时调用整屏 flush。
- 每页构建一个轻量可见状态摘要，用于判断渲染结果是否变化；摘要是页面内部 Implementation，不进入公共 Interface。
- 不在本次改版中实现局部刷新驱动；先通过减少无意义全屏 flush 获得收益，再基于真机测量决定是否深化显示 Module。
- 所有页面使用固定大小栈缓冲；不为布局临时分配堆内存。
- 新增图标使用绘图原语生成，不引入大型位图或完整图标库。

### 13. 兼容与迁移策略

- 首页首先迁移，因为它同时暴露页面直读传感器、电池、网络和 SD 的架构问题。
- 环境、天气和额度随后迁移；每页迁移完成即移除对应业务 Module 的直接 include。
- `ui_page_t` 的生命周期保持不变，避免同时修改页面注册和视觉实现。
- UI V2 使用现有字体生成流程；新增中文文案后重新生成字库并记录固件体积变化。
- ASCII 文案只使用现有字体覆盖范围内的字符；未知天气文本继续使用中文字库。
- 若真机发现黑色实底影响反射屏可读性，优先把反白标题改为粗下划线，不改变整体布局层级。
- UI 改版前后保存四页基线照片，使用同一环境光和拍摄距离比较远读性。

### 14. 完成标准

- 四个页面均不再直接读取传感器、电池、网络或 SD。
- `ui_manager` 不再读取 GPIO 或判断长短按。
- `app_main` 不再包含业务 Module 初始化和页面注册细节。
- WiFi 事件回调不执行阻塞等待；延迟联网后 SNTP 能自动启动。
- 四页共用一致页头、状态图标、页脚和空状态，但主体构图可明显区分。
- 四页在 1 米正常室内光线下能识别核心信息。
- 页面内容未变化时不进行无意义整屏 flush。
- P0-P4 数据含义、页面顺序和 BOOT 刷新行为不退化。
- 新增中文均被字库收录，无空心框。
- 固件大小、最小内部堆、最小 PSRAM 和 `ui_task` 栈高水位有改版前后记录。

## Testing Decisions

- 测试以最高可行 seam 为主：通过 `ui_page_t` 驱动进入、tick 和按键，通过固定 `sys_state` 快照观察最终 400×300 1bpp 帧缓冲，而不是测试私有绘图函数。
- 显示测试使用链接期 host fake Adapter 实现现有显示 Interface，输出 PBM/内存位图；不为了测试给生产页面增加新的公开 Interface。
- `sys_state` 测试覆盖一致快照、并发写入、版本递增、错误状态和字段组合不变量。
- `input_manager` 测试覆盖按键抖动、短按、长按、长按后不补短按、两个按键独立和取消状态映射。
- `app_runtime` 测试只验证可观察启动结果和降级状态，不断言私有初始化函数调用顺序；板级不可恢复失败与可选功能失败必须有不同结果。
- 首页快照场景至少包括：正常、未校时、传感器失败、低电量、WiFi 断开、SD 未挂载。
- 环境页快照场景至少包括：0 条、1 条、稳定数据、明显上升、明显下降、最小值等于最大值。
- 额度页快照场景至少包括：首次等待、正常、超过 80%、旧缓存、桥接服务不可用。
- 天气页快照场景至少包括：晴、阴、雨、未知现象、旧缓存、首次无数据。
- UI snapshot 测试允许对少量动态数字区域做参数化，不允许用大面积忽略掩盖布局回归。
- 刷新测试验证同一可见状态重复 tick 不产生 flush，状态版本变化只产生一次必要刷新。
- 网络测试验证 WiFi 事件回调立即返回，慢速重连由定时器/任务完成，首次 `GOT_IP` 能幂等启动 SNTP。
- SD 测试在深化 Interface 后覆盖路径越界拒绝、并发提交串行化、尾记录撕裂、原子替换中断和未挂载降级。
- 代码库当前没有自动化测试套件，因此 UI host snapshot、纯逻辑 Unity 测试和真机验证作为 R0 新增测试基线；不以私有 Implementation 为测试对象。
- 真机 QA 使用固定检查表：四页照片、按键 20 次短按/长按、断网恢复、拔插 SD、桥接服务关闭/恢复、连续运行 8 小时。
- 真机视觉验收以可读性和稳定性为准，不以像素级截图完全一致替代实际反射屏观察。

## Out of Scope

- 本规格不实现完整音频链路、WakeNet、ASR、TTS 或 agent loop。
- 本规格不实现 Web Search、Browser、MCP、Home Assistant、Telegram 或 Companion。
- 本规格不实现长期记忆日志、n-gram 索引或 embedding；只确保 `storage_sd` 和架构可以承载后续阶段。
- 本规格不引入 LVGL、触摸交互、动态布局、动画、灰阶、颜色主题或完整图标框架。
- 本规格不显示任意 LLM 中文长文本，不扩展完整 CJK 字库。
- 本规格不重写 ST7305 像素打包、初始化序列或刷新协议。
- 本规格不改变天气、Claude 用量桥接协议和数据来源。
- 本规格不重新设计 OTA 分区、安全启动或配网流程。
- 本规格不实现多主题、用户自定义页面排序或可下载 UI 插件。
- 本规格不借视觉改版修复所有历史代码问题；只处理 P5 前置和直接影响页面架构的项目。

## Further Notes

- 本规格依据现有代码和长期设计直接综合，没有额外访谈。
- 推荐验收 seam 是 `sys_state` 快照/命令、语义输入事件和 `ui_page_t` 最终帧缓冲；如果实施前需要调整，应优先保持 seam 数量不增加。
- `codebase-design` 的深 Module 原则影响了本规格：共享视觉能力保留为 `ui_pages` 内部 seam，避免新增公开 UI 框架；`memory_engine` 仍保持单一板载 Implementation。
- `to-spec` 原流程要求发布到 issue tracker 并应用 `ready-for-agent` 标签；当前仓库未提供 issue tracker 和标签配置，因此本次只在项目 `docs` 输出可执行规格，没有创建外部 Issue。
- 实施时应把本规格拆成少量有依赖顺序的任务：网络确定性修复、状态/输入/启动迁移、UI 基础、四页迁移、host snapshot 与真机 QA。
